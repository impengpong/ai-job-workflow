# 投递执行与回执

## 输入闸门

取当前用户已授权平台集合与最新 `apply` 选择的交集。每条必须有精确岗位 ID/URL、公司主体、完整 JD、对应确认简历及锁定招呼语；公司同名或 HR 同公司不足以证明承接目标岗。HR 活跃标签按真实页面记录，未知不是“已知不活跃”。禁止自动扩到官网或小程序；额外付费联系、购买会员和变更通用简历需单独授权。

先查账本及远端历史，已有申请或相同正文/材料不重复发送。跨平台别名只有核实同岗后才能去重。中断且结果未知时，先查询远端，不直接重试。

## 执行

1. 打开精确岗位，验证当前在招与接收人；识别“沟通/感兴趣/加好友”按钮是否会立即产生外发。
2. 按已有授权发送锁定介绍。段间保持双换行；平台硬字数限制生成独立短版并如实标明。
3. 优先会话直接发确认 PDF。不可用时，只有用户授权才发完整清晰的简历页图片；不要为这条岗位替换账号的通用附件。
4. 等待平台明确完成，独立刷新/重新打开会话，逐项核正文、接收人、时间和 PDF/图片内容。上传成功不代表送达。
5. 将正式申请、消息正文、材料分别记录。好友待通过/PDF待回复记外部等待，不循环发送或轮询凑完成。

## 状态词

- `not_started`：未做。
- `submitted`：已操作但还没有独立回读证明。
- `verified`：独立回读与证据符合当前字段；申请 verified 不代表正文或附件 verified。
- `waiting`：正常外部等待，写清条件。
- `blocked`：真实限制，写清原因。
- `unknown`：执行中断，先核远端再重试。

每岗账本三个独立字段 `application` / `message` / `attachment`，各存 `status`、`evidence`、`checked_at`。`scripts/check_ledger.py` 只验证结构和 verified 对应本地证据文件存在，不能自动证明网页真实性或代替主 Agent 审核。

禁止给求职成功率或永久免维护作保证。不要为了录屏重新联系 HR、重复申请或伪造消息气泡。

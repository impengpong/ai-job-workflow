# 一次完整运行

## 1. 先接入，后找岗

确认用户允许的平台、城市、方向、薪资口径、工作年限、雇佣性质及明确排除项。复用已有浏览器，逐平台用一个真实详情页验证身份、完整 JD 和平台限制。Cookie 文件存在或 HTTP 200 均不能代表可用。每个平台单独记录成功、登录缺失、验证码、限频或页面不支持。

## 2. 宽搜与筛选

用岗位名及职责变体搜索，列表先读标题与硬条件；方向相关或标题含糊才读取完整 JD。正常分页/滚动逐次记录条数，无新增即停止，限制出现即停止。对照偏好排除明确冲突，薪资、年限或 HR 活跃未知保留待核。薪资写清月薪/年薪及固定/奖金口径，不擅自换算。猎头公司和实际雇主分别记录。

按平台岗位 ID 去重；跨平台只有确认同公司、同地点、同岗位职责才合并别名。不因为名字接近就合并不同编制。输入统一 `jobs.json`；生成 HTML 后保留原 key 和用户最新选择，更新批次不清空投/拒及留言。

## 3. 公司研究

先按主体/品牌/别名查已有 `companies.json`，只补具体缺项。输出三段：在做什么（产品、客户、需求、收费）；为什么是它（团队、技术、渠道、客户资源）；做得怎样（具日期与口径的产品进展/客户/收入/融资）。事实、分析、未知分开；融资不等于收入、装机不等于活跃、集团成绩不等于所投业务。

来源优先官网、产品页、具名团队、客户案例、投资方及正式披露；媒体为补充，匿名评价是待交叉核实的风险线索。保留原始 URL、标题、访问日期和简短依据，遇失效保留历史记录但不标当前可访问。不要批量复制整篇第三方文章进公开仓库。

## 4. 用户选择与材料

岗位页供用户选择投/不投，也可在会话里确定范围。普通岗位用确认的通用简历＋按 JD 定制介绍；特别心仪才另定制简历。完整简历先于 JD 进入模型，保留完整原始 prompt，追加用户已确认事实边界。检查经历、年限、数字、工具及归属，不把 JD 倒灌为履历。默认段间空一行；平台硬上限单独适配，锁定文本不擅改。

## 5. 执行与验收

按照 `docs/applications.md` 执行，并使用单一账本。单个平台单一执行者持有设备/会话，避免消息连接竞争。每岗分别记录申请、正文、附件状态。恢复任务先读远端历史，不重复发送已成功内容。最后汇报已完成、外部等待、实际阻塞和证据位置。
